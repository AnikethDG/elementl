Enterprise GCP Data Ingestion Framework

A declarative, metadata-driven replication and transformation engine built for NetSuite ERP, Oracle Primavera P6 (JDBC), and Elementl Atlas (HTTP Siting APIs) into Google Cloud Storage and BigQuery, orchestrated with Cloud Composer and Dataform.

2
Define Ingestion Metadata YAML

Create config/sources/netsuite/netsuite_invoices.yaml with SuiteQL query & schedule.

task_id: netsuite_invoices
source:
  type: netsuite
  connection_secret_id: "{{ var.json.common_variables.secrets.netsuite_secret_id }}"
  load_type: incremental
  watermark_column: lastmodifieddate
  query: |
    SELECT id AS invoice_id, tranid AS invoice_number, total AS amount, entity AS customer_id, lastmodifieddate AS last_modified_date
    FROM transaction WHERE type = 'CustInvc' AND lastmodifieddate >= '{{ prev_execution_date | ds }}'
engine:
  type: cloud_run_function
  function_url: "{{ var.json.common_variables.cloud_run_function_url }}"
destination:
  format: PARQUET
  gcs_bucket: "{{ var.json.common_variables.landing_bucket }}"
  gcs_prefix: "netsuite/invoices/"
  bq_dataset: "{{ var.json.common_variables.landing_dataset_netsuite }}"
  bq_table: invoices
  schema_file: config/schemas/netsuite/netsuite_invoices_schema.json
  write_disposition: WRITE_APPEND
orchestration:
  dag_id: dag_ingest_netsuite_invoices
  schedule_interval: "0 3 * * *"
3
Declare in Dataform & Write Silver SQLX Transformation

Add source in dataform/definitions/sources/declarations.js and create dataform/definitions/silver/netsuite/silver_netsuite_invoices.sqlx.

config {
  type: "incremental",
  schema: "silver_netsuite",
  name: "fct_invoices",
  bigquery: { partitionBy: "DATE(ingestion_timestamp)", clusterBy: ["invoice_id", "customer_id"] },
  assertions: { uniqueKey: ["invoice_id"], nonNull: ["invoice_id"] }
}

SELECT
  SAFE_CAST(invoice_id AS INT64) AS invoice_id,
  NULLIF(TRIM(invoice_number), '') AS invoice_number,
  COALESCE(SAFE_CAST(amount AS NUMERIC), 0) AS amount,
  SAFE_CAST(customer_id AS INT64) AS customer_id,
  SAFE_CAST(last_modified_date AS TIMESTAMP) AS last_modified_date,
  CURRENT_TIMESTAMP() AS silver_updated_at
FROM ${ref("invoices")}
QUALIFY ROW_NUMBER() OVER(PARTITION BY invoice_id ORDER BY last_modified_date DESC) = 1

3
Dataform Silver Model with Exclusionary Buffering

In dataform/definitions/silver/atlas/silver_atlas_capable_faults.sqlx, calculate regulatory exclusion zones and deduplicate:

config {
  type: "table",
  schema: "silver_atlas",
  name: "fct_capable_faults",
  assertions: { uniqueKey: ["fault_id"], nonNull: ["fault_id", "buffer_distance_km"] }
}

SELECT
  SAFE_CAST(fault_id AS INT64) AS fault_id,
  COALESCE(TRIM(fault_name), 'Unknown Fault') AS fault_name,
  SAFE_CAST(buffer_distance_km AS FLOAT64) AS buffer_distance_km,
  CASE
    WHEN SAFE_CAST(buffer_distance_km AS FLOAT64) >= 8.0 THEN 'STRICT_EXCLUSION'
    WHEN SAFE_CAST(buffer_distance_km AS FLOAT64) >= 5.0 THEN 'BUFFERED_ANALYSIS_REQUIRED'
    ELSE 'MONITORING_ONLY'
  END AS exclusionary_tier,
  CURRENT_TIMESTAMP() AS silver_updated_at
FROM ${ref("capable_faults")}
QUALIFY ROW_NUMBER() OVER(PARTITION BY fault_id ORDER BY last_updated DESC) = 1

Core Schema Evolution Mechanics (NetSuite & P6)

The framework avoids brittle hardcoded ETL pipelines by employing four layered resilience mechanisms:

1
BigQuery Dynamic Field Addition (ALLOW_FIELD_ADDITION)

Every BigQuery batch load task generated by the DAG factory specifies automated schema evolution flags:

"schemaUpdateOptions": [
  "ALLOW_FIELD_ADDITION",
  "ALLOW_FIELD_RELAXATION"
]

When new columns appear in GCS Parquet files, BigQuery automatically updates the table definition on the fly without table locks, DDL migrations, or ingestion halts. Existing historical partitions seamlessly return NULL for the new column.

2
Self-Describing Parquet Metadata on GCS

Extracted datasets are serialized with PyArrow using the Snappy-compressed Apache Parquet specification. Each Parquet file carries its own embedded schema metadata in the file footer. When a NetSuite SuiteQL query or P6 JDBC extraction projects additional fields, incoming Parquet files include the new column definitions without corrupting previous partitions.

3
Dataform Silver Resilience (Defensive SQLX Casting)

Downstream Silver models isolate BI and reporting from schema drift through defensive projection techniques:

SELECT
  transaction_id,
  -- Safe casting prevents type widening crashes
  SAFE_CAST(custbody_delivery_terms AS STRING) AS delivery_terms,
  -- COALESCE guarantees sensible defaults for historical rows
  COALESCE(SAFE_CAST(udf_environmental_score AS FLOAT64), 0.0) AS environmental_score
FROM ${ref("transactions")}
4
Automated CI/CD Validation & Protection Guardrails

The framework's pre-commit validation suite (composer/dag_factory/validator.py) ensures that schema changes do not violate backward compatibility rules:

  • ✅ Permitted: Adding new fields as NULLABLE mode.
  • ✅ Permitted: Relaxing REQUIRED constraints to NULLABLE.
  • ✅ Permitted: Widening numeric columns (e.g. INTEGER → FLOAT / NUMERIC).
  • ❌ Blocked: Removing or renaming primary key deduplication fields without an active deprecation cycle.

Runbook Operational Troubleshooting

!
NetSuite HTTP 429 Concurrency Limit

Root Cause: NetSuite limits concurrent web service queries per account tier.
Resolution: The framework extractor automatically applies exponential backoff up to 5 retries. Concurrency in Airflow default_args is set to 1.

!
BigQuery Schema Mismatch during Load

Root Cause: Source added a new column or modified a data type.
Resolution: Update config/schemas/{source}/{task}_schema.json and regenerate the DAG using dag_generator.py.

!
Dataform Assertion Failure Alert

Root Cause: Bad record violated unique key or date logic in Silver model.
Resolution: Inspect table in dataform_assertions.* dataset to identify the conflicting row.
